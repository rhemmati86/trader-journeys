# Trader Journeys / سفرهای یک تریدر — v10

**این نسخه یک اسکلت عملیاتیِ آماده اتصال است، نه یک سایت منتشرشده یا متصل‌شده به دیتابیس شما.** تا زمانی که پروژه Supabase و تنظیمات انتشار را خودتان وارد نکنید، سایت در حالت نمایشی محلی کار می‌کند و داده‌ها بین دستگاه‌ها مشترک نیستند.

## چه چیزی در v10 وجود دارد؟

- **حساب مشترک:** اتصال به Supabase Auth برای ثبت‌نام، تأیید ایمیل، ورود و خروج.
- **یک حساب / یک پروفایل:** جدول `profiles` یک شناسه Auth یکتا دارد و trigger پایگاه داده هنگام ساخت حساب پروفایل اولیه می‌سازد.
- **سفرهای ماندگار:** `journey_chapters` برای فصل‌های قابل افزودن، ویرایش، عمومی یا خصوصی‌کردن و حذف.
- **پروفایل عمومی:** صفحه‌های کشف و نمایش پروفایل از داده‌های عمومیِ منتشرشده می‌خوانند.
- **دنبال‌کردن سفر:** جدول `profile_follows` و سیاست‌های دسترسی مربوطه.
- **تفکیک خصوصی/عمومی:** سال تولد، جزئیات نیاز و آدرس کیف پول در `profile_private` هستند و از پرس‌وجوی عمومی قابل خواندن نیستند. آدرس کیف پول در این مرحله به بازدیدکنندگان نمایش داده نمی‌شود.
- **چندزبانه بودن سفرها:** زبان اصلی معرفی، داستان و هر فصل جداگانه نگهداری می‌شود. ترجمه متن‌های دلخواه پس از تنظیم سرویس ترجمه در محیط انتشار فعال می‌شود.
- **حمایت از خود پلتفرم:** صفحه `platform-support.html` و لینک‌های آن اضافه شده‌اند. این بخش فعلاً صرفاً معرفی/«به‌زودی» است؛ هیچ پرداخت یا جمع‌آوری اطلاعات پرداختی فعال نیست.
- **حالت نمایشی:** اگر `supabase-config.js` خالی باشد، سایت واضح اعلام می‌کند اطلاعات فقط در همان مرورگر ذخیره می‌شوند. رمز عبور در حالت نمایشی ذخیره نمی‌شود.

## راه‌اندازی حساب مشترک با Supabase

### 1. ساخت پروژه

یک پروژه در [Supabase](https://supabase.com/) بسازید. برای نسخه آزمایشی از رمز قوی و تنظیمات دسترسی ایمیل استفاده کنید.

### 2. اجرای schema

در Supabase Dashboard به **SQL Editor** بروید و محتوای کامل `supabase/schema.sql` را اجرا کنید. این فایل جدول‌های پروفایل عمومی، اطلاعات خصوصی، فصل‌های سفر و دنبال‌کردن را می‌سازد و RLS و مجوزهای ستون‌ها را تنظیم می‌کند.

اگر پروژه قبلاً از یک نسخه پیش‌نویس همین schema استفاده کرده، بخش‌های migration تلاش می‌کنند سال تولد را از جدول عمومی به `profile_private` منتقل کنند. پیش از استفاده واقعی، روی محیط آزمایشی اجرا و نتیجه را بررسی کنید.

### 3. تنظیم کلید مرورگر

برای جلوگیری از ویرایش دستی فایل‌ها، صفحه `supabase-setup.html` را باز کنید. آدرس پروژه از قبل داخل `supabase-config.js` قرار گرفته است؛ فقط Publishable key را در صفحه تنظیمات وارد و ذخیره کنید. این مقدار در مرورگر نگهداری می‌شود.

```js
window.TJ_SUPABASE_CONFIG = Object.freeze({
  url: "https://YOUR-PROJECT.supabase.co",
  publishableKey: "YOUR_SUPABASE_PUBLISHABLE_KEY"
});
```

برای مرورگر، از **publishable key** یا کلید قدیمی **anon** استفاده کنید. **هرگز** کلید `service_role`، Secret key یا کلید دیتابیس را در فایل‌های سمت مرورگر قرار ندهید. امنیت داده‌ها به RLS و مجوزهای جدول/ستون وابسته است؛ کلید عمومی به‌تنهایی مجوز دسترسی به داده خصوصی نمی‌دهد.

### 4. تنظیم تأیید ایمیل و URLها

در بخش **Authentication → URL Configuration** آدرس سایت نهایی را به‌عنوان Site URL تنظیم کنید و آدرس `login.html` را هم در فهرست Redirect URLs مجاز قرار دهید. اگر تأیید ایمیل فعال باشد، کاربر پس از تأیید ایمیل می‌تواند وارد شود. در این حالت، بعضی جزئیات خصوصی (مانند نیاز و آدرس کیف پول) برای امنیت در فرم ثبت‌نام ذخیره نمی‌شوند و کاربر پس از ورود باید آن‌ها را از داشبورد وارد کند.

### 5. انتشار رایگان اولیه

این پروژه برای استقرار روی **Cloudflare Pages** آماده شده است؛ مسیر `functions/api/translate.js` طبق ساختار file-based Cloudflare Pages به endpoint `/api/translate` نگاشت می‌شود. برای اینکه endpoint ترجمه واقعاً اجرا شود، پروژه را از مخزن Git متصل کنید یا با Wrangler منتشر کنید. **آپلود مستقیم فایل‌های استاتیک از داشبورد، Pages Functions را منتشر نمی‌کند**؛ برای این پروژه از روش پشتیبانی‌شده با Functions استفاده کنید.

این نسخه هنوز منتشر نشده و هیچ آدرس زنده‌ای به آن متصل نیست. پلن‌ها و محدودیت‌های سرویس میزبان را پیش از انتشار عمومی دوباره بررسی کنید.

### 6. تنظیم موتور ترجمه

برای فعال‌کردن ترجمه واقعی داستان‌ها، در **Cloudflare Pages → Settings → Variables and Secrets** مقدار `LIBRETRANSLATE_URL` را روی آدرس پایه یک سرویس LibreTranslate خودمیزبان یا سرویس‌دهنده قابل اعتماد قرار دهید. در صورت نیاز، `LIBRETRANSLATE_API_KEY` را فقط به شکل Secret تنظیم کنید. وقتی این مقادیر تنظیم نشده‌اند، سایت نباید وانمود کند که متن واقعاً ترجمه شده است.

برای توسعه محلی، از `.dev.vars.example` یک فایل `.dev.vars` بسازید و آن را commit نکنید.

## تست دود (Smoke test) پیش از عرضه

1. یک حساب آزمایشی ثبت کنید و تأیید ایمیل را کامل کنید، اگر فعال است.
2. وارد شوید؛ باید همان پروفایل یکتا و داشبورد بارگیری شود.
3. یک فصل خصوصی بسازید و مطمئن شوید در پنجره ناشناس/بدون ورود دیده نمی‌شود.
4. یک فصل عمومی بسازید، پروفایل را صریحاً منتشر کنید و آن را در صفحه کشف سفرها باز کنید.
5. با یک حساب دوم، دنبال‌کردن/لغو دنبال‌کردن را آزمایش کنید.
6. با کاربر ناشناس تلاش کنید `profile_private` را بخوانید؛ باید دسترسی رد شود.
7. ترجمه داستانی با زبان اصلی متفاوت را امتحان کنید؛ اگر موتور ترجمه پیکربندی نشده، باید پیام روشنی ببینید و متن اصلی حفظ شود.
8. در موبایل، فارسی/RTL و انگلیسی/LTR، تنظیمات دارک/روشن و لینک‌های داخلی را بررسی کنید.

## پیش از استفاده عمومی هنوز لازم است

- اجرای schema در پروژه Supabase واقعی و تست آن روی محیط staging؛ این محیط گفتگو به پروژه Supabase شما متصل نیست و schema اینجا روی دیتابیس آنلاین اجرا نشده است.
- بازبینی امنیتی و حریم خصوصی، تست سیاست‌های RLS با حساب‌های جدا و بررسی ایمیل/رمز بازیابی.
- تعیین فرایند واقعی احراز هویت و بررسی داستان‌ها؛ نشان‌های تأیید فعلی جای احراز هویت واقعی را نمی‌گیرند.
- سیاست نگهداری/حذف داده، گزارش تخلف، moderation و پشتیبانی کاربران.
- طراحی قانونی/پرداختی قبل از فعال‌کردن هر نوع کمک مالی یا کیف پول عمومی.
- فعال‌کردن پرداخت برای «حمایت از خود سایت»؛ **در حال حاضر هیچ پرداختی فعال نیست** و توصیه می‌شود این بخش تا تعیین شخصیت حقوقی، گزارش هزینه‌ها، شرایط بازپرداخت/مالیات و ارائه‌دهنده پرداخت غیرفعال بماند.
- اگر دامنه، سرویس ترجمه مدیریت‌شده یا provider دارای هزینه باشد، ممکن است دیگر هزینه صفر نماند. نسخه پایه قابل شروع با پلن‌های رایگان است، اما هزینه‌ها و محدودیت‌های آینده به سرویس‌های انتخاب‌شده بستگی دارد.

## پوشه‌ها و فایل‌های مهم

- `supabase/schema.sql` — schema، RLS و triggerهای پروفایل.
- `supabase-config.js` — URL و publishable key عمومی پروژه.
- `backend.js` — لایه adapter بین UI و Supabase/local demo.
- `functions/api/translate.js` — proxy ترجمه در سمت سرور.
- `platform-support.html` — صفحه آینده حمایت از هزینه‌های خود پلتفرم (پرداخت غیرفعال).
- `dashboard.html` / `edit-profile.html` — مدیریت سفر و پروفایل خود.
- `explore.html` / `public-profile.html` / `journey.html` — کشف و مشاهده سفرهای عمومی.

## منابع رسمی برای راه‌اندازی

- [Supabase API keys](https://supabase.com/docs/guides/getting-started/api-keys) — انتخاب کلید publishable برای کد مرورگر و نگهداری Secret key فقط در سمت سرور.
- [Supabase Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security) — نحوه کنترل دسترسی به ردیف‌های پایگاه داده.
- [Supabase column-level privileges](https://supabase.com/docs/guides/database/postgres/column-level-security) — محدودسازی ستون‌های قابل خواندن و نوشتن.
- [Cloudflare Pages Functions](https://developers.cloudflare.com/pages/functions/) و [routing](https://developers.cloudflare.com/pages/functions/routing/) — نشر endpoint ترجمه از پوشه `functions/`.

## کلیدهای محرمانه

فایل `.gitignore` از `.dev.vars` و فایل‌های محیط محلی جلوگیری می‌کند؛ بااین‌حال پیش از انتشار، commitها را بازبینی کنید و هیچ Secret/service_role key یا اطلاعات واقعی کاربر آزمایشی را داخل مخزن نگذارید.
